## 2. 未覆盖项（明确不做或本轮未做）

| 类别                               | 状态     | 理由                                                |
| ---------------------------------- | -------- | --------------------------------------------------- |
| 国际化 / RTL                       | **不做** | 受众为单一中文群体（ADR-0008）                      |
| 表单与表单校验/恢复                | **N/A**  | 站点无任何表单输入                                  |
| 登录/权限/会话                     | **N/A**  | 无账号体系，隐私政策明确「无需注册」                |
| 支付与订单                         | **N/A**  | 无收费功能                                          |
| API 层（请求/超时/重试/取消/缓存） | **N/A**  | 无后端交互；已在 ADR-0005 说明为何不建空壳抽象      |
| 服务端状态管理                     | **N/A**  | 数据在构建期确定                                    |
| 邮件模板                           | **N/A**  | 无邮件发送功能                                      |
| 第三方集成                         | **不做** | 无统计、无客服 SDK、无登录组件（隐私承诺）          |
| 灰度发布 / 监控告警                | **不做** | 纯静态站，回滚基于 Git 与发布目录（见 rollback.md） |
| 弱网 / 离线                        | **部分** | 图片懒加载 + 相邻预取；无 Service Worker（P2-07）   |
| 真实用户性能数据                   | **不做** | 无统计（隐私承诺），仅本地 Lighthouse 抽查          |
| 单元测试覆盖 UI 组件               | **不做** | 组件在构建期渲染，用视觉回归 + E2E 替代（ADR-0006） |
| 第三方安全审计                     | **不做** | 无资源；依赖漏洞用 `npm audit`（当前 0）            |
| 无障碍第三方审计                   | **不做** | 用 axe + 人工抽查替代（AS-06）                      |

## 3. 残余风险

| 风险                                                   | 等级 | 触发条件                   | 当前缓解                                       | 处置                                 |
| ------------------------------------------------------ | ---- | -------------------------- | ---------------------------------------------- | ------------------------------------ |
| 根目录产物过期导致线上回退到旧版本                     | 中   | 改源码后未执行 `release`   | `verify`/CI 的 `check:release` 门禁            | 执行 `npm run release` 后提交推送    |
| 视觉基线跨平台漂移                                     | 中   | 升级 Chromium 或系统字体   | 基线文件名含平台后缀                           | 在目标平台重建基线                   |
| 依赖主版本升级引入破坏                                 | 中   | 手工升级 astro/rehype 插件 | 版本全部锁定 `--save-exact`；`verify` 全跑     | 回退 `package-lock.json` 并 `npm ci` |
| `github-slugger` 与 `rehype-slug` 版本分叉导致锚点失配 | 低   | 单独升级其一               | 两者均锁定确切版本                             | 同步升级并跑法律页 E2E               |
| 内容过期（上架状态、招生数据）                         | 中   | 应用上架 / 招生季变化      | 数据集中在 `src/data`，改动成本低              | 按 FAQ 与 Hero 文案更新              |
| 备案信息变更                                           | 低   | 主体或号段变更             | 三处集中引用 `site.filing`                     | 改一处即可（v1 需改三处）            |
| Node 版本不满足                                        | 低   | 使用 Node < 24             | `engines` 声明 + CI 固定 Node 24 + README 说明 | 升级 Node 或改用预编译脚本           |
| 第三方字体许可                                         | 低   | 上游协议变更               | Fraunces 为 OFL-1.1，随包分发                  | 切换为系统衬线栈                     |
