### 5.3 非缺陷但值得记录的调整

- Node 版本从「≥22」收敛到「≥24」，与 Astro 实际运行要求、CI 和本地验证环境一致；
- 新增 38 个单元用例中的设备元数据断言，避免「文案说 13 Pro Max、素材却是别的机型」；
- 新增设备框令牌，避免在组件里硬编码苍岭绿色值；
- 将设备框从通用边框改为可复用组件，Hero 与轮播不再各写一套。

## 7. 做对了什么

1. **事实源先行**：先核对仓库、线上逐字节一致，再决定重构对象，避免在错误的仓库上重做。
2. **把发布风险当成 P0**：在不知道平台输出目录的情况下，用「`dist/` + 根目录同步」双兼容，最终线上证明平台确实从根目录服务。
3. **门禁不是形式**：独立巡检发现 `#intro` 缺 `id`；链接检查、视觉回归与 E2E 分别拦住了不同层次的问题。
4. **CI 失败被当成产品缺陷修复**：没有用「本地能跑」掩盖 Node 版本不匹配，而是统一到可验证的 Node 24。
5. **设备框按真实硬件设计**：令牌、组件、数据、测试、文档、线上证据同一条链路，避免只改一张图。

## 8. 做得不够好的地方

| 问题                                 | 影响                                                  | 改进                                                        |
| ------------------------------------ | ----------------------------------------------------- | ----------------------------------------------------------- |
| Node 版本声明与 Astro 实际要求不一致 | 首次 `main` CI 失败，浪费一轮发布                     | 把 `engines` 纳入 CI 启动前检查；升级依赖时同步核对 engines |
| 视觉基线在本地更新，未在 CI 生成     | 基线仓库约 17 MB；跨平台仍需人工注意                  | 评估 CI 生成基线或按需下载；补 `webkit` 项目                |
| 根目录产物与源码同库                 | 仓库增加约 31 MB                                      | 平台配置确认后评估发布分支或对象存储（P1-01）               |
| 设备框改版发生在上线之后             | 需要二次发布、二次线上验证                            | UI 改版尽量与主版本一起验收；把视觉基线重建纳入发布清单     |
| 仍缺真人无障碍与真机验证             | axe 不能替代 VoiceOver；Chromium 不能替代 Safari/真机 | 固定人工验收清单并记录结果（P1-03）                         |

## 10. 回滚方案

| 级别 | 场景                     | 动作                                                                  |
| ---- | ------------------------ | --------------------------------------------------------------------- |
| L1   | 单次文案/图片/设备框问题 | `git revert <commit>` → `npm run release` → 推送                      |
| L2   | v2 结构性问题            | 从 `backup/pre-refactor-v1` 取回 v1，按平台根目录发布                 |
| L3   | 彻底放弃 v2              | 将 `main` 重置到 `backup/pre-refactor-v1`（需人工批准，保留 v2 分支） |

完整命令、演练输出与注意事项见 [`docs/operations/rollback.md`](rollback.md)。
