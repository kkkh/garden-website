# ADR-0010：已知限制与残余风险的显式接受

- 状态：已采纳
- 日期：2026-10-23

## 背景

任务要求禁止使用「完美/零缺陷/极致/已完成」作为结论，必须显式列出已知缺陷、未覆盖项、假设、残余风险。
本 ADR 把这些内容固化为「经过评估并接受」的决策，而不是散落在报告中。

## 接受清单

### A. 已被接受的实现限制

| 编号 | 限制 | 为什么不修 | 影响 | 若未来要修 |
| --- | --- | --- | --- | --- |
| A1 | 生产部署未执行 | 缺少 EdgeOne 平台凭据；协议将「生产部署」列为必须暂停项 | 线上仍是 v1 | 按 `docs/operations/deployment.md` 由有权限者执行 |
| A2 | 视觉基线仅覆盖 Chromium | 单一引擎降低 CI 下载体积与时间；本项目不使用引擎特有 API | Safari/Firefox 的具体像素差异未被自动守护 | 增加 `webkit` / `firefox` 项目并各自生成基线 |
| A3 | `prefers-contrast: more` 与 `forced-colors` 无自动化验证 | Playwright 无法可靠模拟这两个媒体特性 | 规则正确性依赖人工（Windows 高对比度、macOS 增强对比） | 人工在真机/虚拟机验证并记录截图 |
| A4 | 架构图缺少长文本替代描述 | 图文内容来自第三方设计稿，撰写长描述需校方确认口径 | 读屏用户获得的信息量少于视觉用户 | 为 10 张图补 `aria-describedby` 长描述 |
| A5 | 界面文案全部硬编码中文，无 i18n | 见 ADR-0008 | 无法切换语言 | 在 `src/data` 增加语言维度 |
| A6 | 图片仍为原始分辨率资产（1284×2778 / 1600×1240） | 保留源文件便于再生成派生尺寸；构建期已产出 AVIF/WebP 派生 | 仓库体积约 9 MB | 源图迁移到对象存储（会引入外部依赖） |
| A7 | `apple-app-site-association` 的 `appID` 无法在本地验证 | 需 Apple Developer 账号与真机 | 若 appID 错误，Universal Links 不生效（不影响网页） | 上架后真机验证，必要时更新该文件 |
| A8 | 埋点为自建本地缓冲，无服务端聚合 | 站点承诺无第三方统计；本地缓冲已满足 E2E 断言 | 无法获得真实访问分析 | 若确需分析，须先更新隐私政策 |
| A9 | 单页 `region` 地标豁免 | 语义噪声大于收益（见 ADR-0008） | axe 的 `region` 规则不通过（不阻塞） | 为每个 section 指定 `aria-labelledby` 并加 `role="region"`（已部分具备） |
| A10 | 无 Service Worker / 离线能力 | 内容站离线收益低，且会引入缓存陈旧治理成本 | 断网不可访问 | 引入 Workbox 并制定版本治理策略 |

### B. 未覆盖的测试项

| 项 | 现状 | 原因 |
| --- | --- | --- |
| 跨浏览器视觉回归 | 仅 Chromium | A2 |
| 真机（iOS Safari / Android Chrome）验证 | 未做 | 需要真机与人工操作，属于独立验收环节 |
| 实际屏幕阅读器（VoiceOver / NVDA）朗读验证 | 未做 | axe 只能发现规则级问题，不能替代真人朗读测试 |
| 打印输出的 PDF 分页效果 | 仅实现样式，未生成 PDF 对比 | 无自动化手段与明确验收标准 |
| 压力/并发测试 | 不适用 | 纯静态托管，无服务端计算 |
| 旧浏览器（如 Safari 15 以下） | 未验证 | 目标用户为现代移动端；`aspect-ratio`、`<dialog>`、`color-mix` 等特性在旧版不可用 |

### C. 假设（完整版见 `docs/acceptance/assumptions.md`）

| 编号 | 假设 | 若假设不成立的后果 |
| --- | --- | --- |
| AS-01 | `garden-website` 为线上事实源（已用字节级 diff 验证） | 重构方向错误 |
| AS-02 | 线上托管为 EdgeOne Makers，站点根可从仓库根改为 `dist` | 部署方案需改写 |
| AS-03 | 应用未上架，暂无 App Store 链接 | FAQ 与 Hero 文案需更新 |
| AS-04 | 学校官网公开信息可继续聚合，内容版权归学校 | 需法务复核 |
| AS-05 | 主题偏好仅本地存储，不构成个人信息收集 | 隐私政策需重新评估 |
| AS-06 | 独立验收由独立子代理 + 人工复核完成，不等同于第三方机构审计 | 验收强度被高估 |

### D. 残余风险

| 风险 | 等级 | 说明 | 触发条件 |
| --- | --- | --- | --- |
| 部署目录未改导致线上 404 | 高 | 唯一破坏性部署变更 | 发布时忘记改 EdgeOne 输出目录 |
| 视觉基线漂移误报 | 中 | 字体或浏览器版本变化导致像素差异 | 升级 Chromium / 系统字体 |
| `github-slugger` 与 `rehype-slug` 版本漂移 | 低 | 两者主版本不一致时 slug 规则可能分叉 | 单独升级其一 |
| Node 版本差异导致 `.ts` 直接加载失败 | 低 | 脚本依赖 Node 22+ 的 TS 支持 | 使用 Node 20 或更低 |
| 第三方字体许可变更 | 低 | Fraunces 为 OFL-1.1，随包分发 | 上游改协议（可能性极低） |
| 内容过期 | 中 | 应用上架后「即将上架」文案与 FAQ 需更新 | 应用上架 |
| 备案信息变更 | 低 | 需同步 3 处（页脚、关于、结构化数据） | 备案主体或号段变更 |

## 决策

**接受上述限制与风险**，理由：

1. 每一项都有明确的「不修」原因（缺少凭据、缺少需求、无自动化手段、复杂度不划算），而不是遗漏；
2. 每一项都有可执行的后续动作与影响范围说明；
3. 这些限制不触及可用性熔断（可安装、可构建、可运行、核心流程不崩溃、可回滚）。

同时明确：**本项目的验收结论只能表述为「在下列证据与已知缺陷下达到验收标准」**，不得表述为「完美 / 零缺陷 / 极致」。

## 验证

- 本 ADR 的 A/B/C/D 四张表需在每次大版本发布前复核；
- 若某项限制被修复，应在对应条目注明「已于 <date> 修复」并保留原始记录。
