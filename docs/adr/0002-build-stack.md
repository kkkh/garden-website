# ADR-0002：构建栈 —— Astro 静态输出 + TypeScript strict

- 状态：已采纳
- 日期：2026-10-23

## 背景

v1 是零构建的纯静态站：3 个 HTML 手写全站结构，1 个 965 行 CSS，1 段 89 行内联 IIFE。
问题不在于「能不能跑」，而在于：

- 页头、页脚在 3 个页面各存一份，已经出现版权措辞、欢迎语、CSS 版本参数不一致；
- 89 行脚本无类型、无测试、无模块边界；
- 没有资源优化管线：22 张 1284×2778 JPG 原图直出，移动端首访成本高；
- 后端与 CI 无任何门禁：错误只能靠人工肉眼发现。

任务要求「架构优雅度、可维护性、类型安全、测试完整性」作为质量目标，且明确「性能不作为选型否决项」。
同时任务给出**可用性熔断**：不可构建、不可运行、不可回滚即视为未完成。

## 候选方案与决策矩阵

| 维度                 | 保持零构建           | **Astro 7 静态输出 + TS strict（选中）**       | Next.js（SSG/App Router） | Vite + React/Vue SPA     | 11ty + Nunjucks |
| -------------------- | -------------------- | ---------------------------------------------- | ------------------------- | ------------------------ | --------------- |
| 交付形态             | 手写 HTML            | 纯静态 HTML（无运行时框架）                    | 静态 HTML + 大量运行时 JS | 需 JS 才能渲染           | 静态 HTML       |
| 组件复用             | 无（复制粘贴）       | 强（`.astro` 组件 + 布局）                     | 强                        | 强                       | 中              |
| 类型安全             | 无                   | TypeScript strict + `astro check`              | TypeScript                | TypeScript               | 弱（JS 模板）   |
| 资源优化             | 无                   | 内建：AVIF/WebP、多尺寸、`sharp` 派生          | 内建                      | 需插件                   | 需插件          |
| 内容建模             | 无                   | Content Collections + Zod 校验                 | MDX/Contentlayer          | 需自建                   | 数据文件        |
| SEO/站点地图         | 手写                 | 列表 + sitemap 集成                            | 内建                      | 需自建                   | 插件            |
| 设计表达力           | 完全自由（但难复用） | 完全自由（原生 CSS + 组件）                    | 受框架约束                | 受框架约束               | 中等            |
| 生态质量             | 无                   | 良好、官方维护、社区活跃                       | 极好                      | 极好                     | 一般            |
| 迁移成本             | 0                    | 中（一次性重写结构）                           | 高                        | 高                       | 中              |
| 引入的运行时成本     | 0                    | 0（静态输出，无框架运行时）                    | 明显                      | 明显                     | 0               |
| 与「静态站」定位契合 | 契合                 | **契合且补足工程能力**                         | 过重                      | 过重（SPA 不适配内容站） | 契合            |
| 回滚难度             | —                    | 低（回退到 `backup/pre-refactor-v1` 分支即可） | 高                        | 高                       | 中              |

**决策：采用 Astro 7 静态输出 + TypeScript strict。**

## 理由

1. **交付形态不变**：Astro 的静态输出仍是普通 HTML/CSS/JS，不引入客户端框架运行时，符合「静态官网」定位，也不突破可用性熔断。
2. **直接消除 v1 的具体缺陷**：布局与组件复用（头尾单一来源）、Content Collections + Zod（法律文本受 schema 校验）、内建图片管线（`<Picture>` 生成 AVIF/WebP + 多尺寸）、sitemap 集成。
3. **类型安全可被门禁验证**：`astro check` 覆盖 53 个文件、0 错误，作为 CI 阻塞项。
4. **可回滚性明确**：v1 完整保存在 `backup/pre-refactor-v1` 分支，线上仍运行 v1，切换是「发布目录」级别操作。
5. **不引入无收益复杂度**：没有状态管理库、没有 API 层（本站无后端交互）、没有微前端、没有 GraphQL。

## 替代方案与否决理由

- **保持零构建**：无法解决头尾重复、无类型、无资源优化、无门禁四类问题；且任务明确要求架构与测试完整性。
- **Next.js**：为 4 个静态页面引入框架运行时与服务器概念，收益低、复杂度高，违反「禁止无收益引入重型 UI 库或新构建链」。
- **Vite + SPA 框架**：内容站首屏依赖 JS，属于可访问性与稳健性退步。
- **11ty**：更轻，但缺少内建图片管线与类型检查，需要额外插件拼装，长期维护质量低于 Astro。

## 影响

| 影响面 | 变化                                                                                                                    |
| ------ | ----------------------------------------------------------------------------------------------------------------------- |
| 构建   | 新增 `npm ci && npm run build`，产物在 `dist/`                                                                          |
| 部署   | 站点根从「仓库根目录」变为 `dist/`（见 ADR-0007）                                                                       |
| 依赖   | 6 个运行时依赖（astro、sitemap、sharp、markdown-remark、rehype 插件、fontsource 字体）+ 15 个开发依赖，全部锁定确切版本 |
| 页面源 | 3 个 HTML → 3 个 `.astro` 页面 + 1 个动态路由 + 内容集合                                                                |
| 旧链接 | 保持 `.html` 后缀（`build.format: 'file'`），`/privacy.html`、`/agreement.html` 不失效                                  |

## 风险与回滚

| 风险                             | 缓解                                            | 回滚                                                     |
| -------------------------------- | ----------------------------------------------- | -------------------------------------------------------- |
| Astro 大版本升级带来的破坏性变更 | 版本锁定到 `7.4.2`；升级需重跑 `npm run verify` | 回退 `package.json` + `package-lock.json`，`npm ci` 重建 |
| 构建耗时增加（图片派生约 20s）   | 可接受；缓存 `dist/` 与 `.astro/`               | 无需回滚，仅影响体验                                     |
| 团队不熟悉 Astro                 | 已写入 README 与 ADR，目录结构按领域分层        | —                                                        |
| dist 站点根配置错误导致线上 404  | 部署前按 `docs/operations/deployment.md` 校验   | 平台侧把发布目录改回仓库根并重新发布 v1 分支             |

## 验证

```bash
npm ci
npm run build          # 生成 dist/，含 4 个 HTML、sitemap、manifest
npm run verify         # 全部门禁，含构建与 100 项 E2E
```
