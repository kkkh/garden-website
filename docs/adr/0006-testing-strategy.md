# ADR-0006：测试与验收策略

- 状态：已采纳
- 日期：2026-10-23

## 背景

v1 没有任何自动化测试、Lint、类型检查或 CI。
任务要求：关键组件单测、核心流程 E2E、可访问性检查、视觉回归、构建检查；
并要求「实施与验收角色分离」「门禁失败不得宣称完成」「所有『顶级』必须落到可检查工件」。

## 决策

建立四层门禁 + 一层独立验收：

| 层         | 工具                                  | 覆盖对象                                                                                                 | 失败处理                 |
| ---------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------ |
| 设计令牌   | 自建脚本（生成器一致性 + 硬编码扫描） | `src/**` 全部样式与组件                                                                                  | 阻塞发布                 |
| 配色可读性 | 自建脚本 + `culori`（WCAG 2.1）       | 33 项语义色组合（浅/深）                                                                                 | 阻塞发布                 |
| 静态检查   | `astro check`、ESLint、Prettier       | 53 个文件                                                                                                | 阻塞发布                 |
| 单元测试   | Vitest                                | 轮播纯函数、主题逻辑、数据契约、结构化数据                                                               | 阻塞发布                 |
| 端到端     | Playwright + axe-core                 | 页面结构/SEO/结构化数据、轮播、灯箱、主题、导航、法律页、404、外链安全、a11y、响应式、减弱动效、视觉回归 | 阻塞发布                 |
| 独立验收   | 独立子代理 + 人工复核                 | 覆盖矩阵逐项                                                                                             | 缺陷按 P0/P1/P2 分级闭环 |

### 关键设计取舍

1. **测试对象是构建产物**：Playwright 使用 `astro preview` 提供 `dist/`，而不是 dev server，避免「dev 正常、构建后异常」。
2. **a11y 判定口径明确**：axe 使用 `wcag2a/wcag2aa/wcag21a/wcag21aa/best-practice` 标签，仅将 `serious` / `critical` 视为阻塞；仅豁免 `region` 规则（单页多区块布局下的地标粒度争议，已在 ADR-0010 记录）。
3. **视觉回归多视口多主题**：桌面/平板/手机 × 浅色/深色，共 48 张基线；`maxDiffPixelRatio: 0.02`，禁用动画与光标以稳定截图。
4. **弱视/减弱动效作为独立项目**：`prefers-reduced-motion` 用独立 Playwright 项目验证内容可见性与动画关闭。
5. **埋点可断言**：`track()` 把事件写入 `window.__gardenEvents` 并派发 `garden:event`，E2E 直接断言（如轮播切换产生 `showcase:change`），不依赖任何外部分析服务。
6. **不追求覆盖率数字**：覆盖率仅生成报告（`reports/coverage`），不作为门禁，避免为指标写无意义测试。

## 理由

- 门禁必须**可重复、可在 CI 执行、失败即阻塞**，否则「零缺陷」只是形容词；
- 视觉回归是「设计系统是否被破坏」最直接的工件；
- a11y 用成熟规则集（axe）而非自评，减少主观性；
- 独立验收必须由不同角色执行，实施者自评不成立。

## 替代方案

| 方案                              | 否决理由                                                  |
| --------------------------------- | --------------------------------------------------------- |
| 只做单元测试                      | 无法覆盖真实渲染、ARIA、响应式与视觉                      |
| 只做人工目测                      | 不可重复、不可回归，v1 的问题正是这样积累的               |
| 引入 Jest + jsdom 做组件测试      | 静态站组件在构建期渲染，jsdom 无法验证真实 CSS 与图片管线 |
| 引入 Percy/Chromatic 等视觉云服务 | 需要账号与上传产物，与「不引入外部服务」及隐私承诺冲突    |
| 把覆盖率设为 90% 门禁             | 会诱导写「为覆盖率而写」的测试，偏离真实风险              |

## 影响

| 影响面   | 变化                                                                                     |
| -------- | ---------------------------------------------------------------------------------------- |
| 开发流程 | 提交前跑 `npm run verify`（约 3–4 分钟）                                                 |
| 产物     | `reports/`（Playwright HTML/JSON、覆盖率）、`test-results/`（失败附件、trace），均不入库 |
| 视觉基线 | 入库到 `tests/e2e/visual.spec.ts-snapshots/`（约 17 MB），评审变更时需检查 diff          |
| 依赖     | 新增 `@playwright/test`、`@axe-core/playwright`、`vitest`、`culori`（均锁定版本）        |

## 风险与回滚

| 风险                                                 | 缓解                                                     | 回滚                                                            |
| ---------------------------------------------------- | -------------------------------------------------------- | --------------------------------------------------------------- |
| 视觉基线在跨平台（macOS vs Linux）字体渲染差异下抖动 | 基线文件名带平台后缀（`-darwin`）；CI 与本地各自维护基线 | 若 CI 引入 Linux 基线，用 `--update-snapshots` 在 CI 容器内重建 |
| 视觉基线体积较大                                     | 仅保留关键区块与组件状态，非全页全量                     | 删除基线并重新生成                                              |
| 测试耗时增加                                         | 并行执行（默认 workers）、`reuseExistingServer`          | 按需只跑子集（`--project` / 具体 spec）                         |
| 图片基线难以人工判读                                 | 报告同时输出 diff 图与 trace                             | —                                                               |

## 验证

```bash
npm run verify            # 全部门禁，exit 0
npx playwright test --reporter=html   # 查看可视化报告
npm run test:visual:update            # 设计变更后重建基线
```
