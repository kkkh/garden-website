# v3 版本规划：上架就绪、更新日志与安全加固

## Context

官网当前是 v2：单页首页 + 隐私政策 + 用户协议 + 404，应用状态为「即将上架 App Store」，首页没有任何下载入口，`MobileApplication` 结构化数据停在 `PreOrder`。应用上架后，官网需要能在**不改结构**的前提下切换为真实下载入口，并能持续发布版本更新信息；同时 v2 遗留的几项工程风险（HTTP 未强制跳转、缺安全响应头、图片源文件偏大）应在 v3 收口。

本规划基于以下默认假设（未额外确认，按最稳妥方案设计）：

- 应用**尚未上架**，v3 先交付「可配置下载入口 + 未上架优雅降级」，上架时只改数据文件；
- 保持**纯静态、无后端、无前端框架、无第三方统计**的既有边界；
- **分阶段交付**，每阶段可独立上线、独立验收；
- 不做国际化、不做每功能一页、不做 PWA/离线。

目标：上架当天，官网从「即将上架」切到「可下载」只需改 `src/data/appStore.ts` 与 `src/data/releases.ts` 两个文件，并重新发布。

## 阶段 P0：数据契约与状态机（无视觉变化）

**改什么**

- 新增 `src/data/appStore.ts`：`AppStoreStatus = 'coming-soon' | 'live'`、`appStoreId`、`url`、`badgeAlt`、`qrAlt`、`smartBannerEnabled`、`appArgument`；导出 `hasDownloadUrl()`、`isAllowedAppStoreUrl()`（仅允许 `https://apps.apple.com`）、`appAvailability`。
- 新增 `src/data/releases.ts`：`Release { version, status, date, title, summary, changes[] }`、`releaseCategoryMeta`（新增/改进/修复）、`getRecentReleases(limit)`、`getLatestReleasedRelease()`、`releaseAnchor()`、`groupReleaseChanges()`。首条数据用 `status: 'upcoming'`、`date: null`，不伪造发布日期。
- 新增 `src/data/appInfo.ts`：`minimumOS`、`devices`、`languages`、`price`、`privacy`、`seller`；`version`/`releaseDate` 从 `releases` 派生；`size`/`ageRating` 未上架时为 `null`，UI 显示「上架后公布」。
- 修改 `src/data/site.ts`：`availability` 改为引用 `appAvailability`（字符串值不变）；`assets` 增加 `ogImages`、`appStoreBadge`、`appStoreQr`；新增 `resourceNavigation`（应用下载 / 更新日志）。
- 修改 `src/lib/format.ts`：新增 `formatDateFromIso(iso)`，复用现有日期格式化。

**验收**：`npm run build` 后首页 HTML 与改动前逐字节一致；`npm run verify` 全绿；70 张视觉基线全部通过。

## 阶段 P1：下载入口与应用信息区（`coming-soon` 即可上线）

**改什么**

- 新增 `src/components/app/AppStoreBadge.astro`：`live` 时渲染官方徽章链接（`target="_blank"` + `rel="noopener noreferrer"` + `data-track`），徽章自托管、不重绘、不改色，白色底容器保证深色主题可读；`soon` 时不渲染。
- 新增 `src/components/app/QrCode.astro`：`live` 时渲染二维码 `<figure>` + 可见 `figcaption` 文字链接（二维码不是唯一入口）；`soon` 时渲染「上架后在此显示下载二维码」占位文本，不渲染空 `img`。
- 新增 `src/components/home/AppInfoSection.astro`：`id="download"`、`data-app-store-state={hasDownloadUrl() ? 'live' : 'soon'}`；左侧应用图标 + 下载区（徽章/二维码或「上架提醒」邮件按钮），右侧复用 `.spec-list` 展示版本、大小、兼容性、价格、语言、年龄分级、开发者、更新日期，复用 `.system-list` 展示隐私摘要；链接到 `/privacy.html` 与 `#system`。
- 修改 `src/pages/index.astro`：在 `FactBand` 之后插入 `<AppInfoSection />`。
- 修改 `src/data/faq.ts`：第一条答案按 `hasDownloadUrl()` 分支；FAQ 仍保持 6 条（`home.spec.ts` 有 `toHaveCount(6)`）。
- 新增 `src/lib/app-store.ts`：`appleItunesAppContent()`，仅在 `live` 且 `appStoreId` 为纯数字时返回 `app-id=...`。
- 修改 `src/components/seo/Seo.astro`：输出 `apple-itunes-app` meta（有值时）。
- 修改 `src/lib/schema.ts`：`mobileApplicationSchema(config, info)`，`live` 时 `offers.availability = InStock`、`offers.url`、`installUrl`、`softwareVersion`、`datePublished`、`privacyPolicy`；`soon` 保持 `PreOrder`。

**验收**

- 线上（`soon`）：首页出现 `#download`，无任何 `apps.apple.com` 外链、无二维码、无 `apple-itunes-app`，有邮件提醒 CTA；axe 通过。
- 视觉基线：只更新 4 张 `home-full-*`，其余 66 张不动。

## 阶段 P2：更新日志页与每页独立 OG

**改什么**

- 新增 `src/components/changelog/ReleaseTimeline.astro`：`variant: 'preview' | 'full'`；版本条目 `article` + `aria-labelledby`，`<time datetime>`（无日期显示「待上架」），三类变更用文字标签区分；预览最多 3 条并链到完整页；版本锚点 `#v1-0-0`。
- 新增 `src/pages/changelog.astro`：`BaseLayout` + `type="article"` + `jsonLd=[websiteSchema, breadcrumbSchema, changelogSchema]`；有日期时传 `publishedTime/modifiedTime`；OG 用 `/og/og-changelog.png`。
- 修改 `src/pages/index.astro`：在 `SystemSection` 与 `FaqSection` 之间插入 `ReleaseTimeline`（预览 3 条）。
- 修改 `src/components/chrome/SiteFooter.astro`：在站点导航追加 `resourceNavigation`（`#download` 由现有 `resolve()` 自动正确指向首页锚点）。
- 修改 `src/lib/schema.ts`：新增 `changelogSchema(releases)`，输出 `ItemList`（`ItemListOrderDescending`），每项 `SoftwareApplication` + `softwareVersion` + `datePublished`（仅已发布）+ 锚点 URL。
- 修改 `src/layouts/BaseLayout.astro` 与 `src/layouts/LegalLayout.astro`：透传 `image` / `imageAlt`（`Seo.astro` 已支持，无需改 Seo）。
- 修改 `src/pages/[slug].astro`：按 `entry.id` 映射 `og-privacy.png` / `og-agreement.png`。
- 新增 `scripts/generate-og.mjs`：用现有 `sharp` + 设计令牌色生成 3 张 1200×630 PNG 到 `public/og/`，**一次性执行并提交产物**，不进 `build`，避免 CI 字体差异与构建膨胀；标题文案从 `site`/常量读取。
- 修改 `scripts/sync-root.mjs` 的 `SYNC_TARGETS`：加入 `changelog.html`、`brand`、`qr`（保证根产物同步）。

**测试与基线**

- 新增 `tests/e2e/changelog.spec.ts`：页面 200、`h1` 唯一、条目数与数据一致、`<time>`/「待上架」、预览 ≤3 条、锚点可跳转、canonical/OG 正确、无第三方请求。
- 修改 `tests/e2e/a11y.spec.ts` 页面数组加入 `/changelog.html`。
- 修改 `playwright.config.ts` 的 `mobile-light` `testMatch` 加入 `changelog`。
- 视觉新增 4 张：更新日志页（desktop-light / desktop-dark / mobile-light / webkit），tablet 跳过；合计 74 张。

**验收**：`/changelog.html` 200；首页预览正确；三张新 OG 200 且 1200×630；sitemap 自动收录；axe/视觉全绿。

## 阶段 P3：安全与工程加固

**改什么**

- 新增 `edgeone.json`（若平台支持，部署后以 `curl -I` 验证；不支持则按同一份内容在控制台配置）：
  - `Content-Security-Policy`：`default-src 'self'; img-src 'self' data:; font-src 'self'; style-src 'self' 'unsafe-inline'; script-src 'self' 'unsafe-inline'; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'; upgrade-insecure-requests`（内联样式与主题脚本决定了必须允许 `unsafe-inline`）；
  - `Referrer-Policy: strict-origin-when-cross-origin`、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()`；
  - 静态资源缓存：`/_astro/*` 一年 immutable，`/*.html` 短缓存。
- HSTS 与「HTTP → HTTPS 301」在 EdgeOne 控制台开启：先 `max-age=300` 验证，稳定后改一年，不开 `preload`；代码侧只做文档化。
- 新增 `tests/unit/config.test.ts`：解析 `edgeone.json` 断言关键头与 CSP 指令存在。
- 图片源文件压缩：新增 `scripts/optimize-assets.mjs`（一次性执行）——架构图转无损 WebP 并逐像素校验；截图用 mozjpeg 重编码且 PSNR ≥ 42 dB 才替换；失败保留原图。同步修改 `src/data/architecture.ts` 的 import 后缀。
- 修改 `.prettierignore` / `eslint.config.mjs`：忽略根产物中的 `brand/`、`qr/`、`changelog.html`。

**验收**：`curl -I https://jl.43322.cn/` 出现 CSP/Referrer/XCTO/XFO/Permissions-Policy；`curl -I http://jl.43322.cn/` 返回 301；压缩后源码资源体积下降且 74 张基线全过。

## 验证方式（每个阶段结束都执行）

```bash
npm run verify          # tokens/contrast/typecheck/lint/format/unit/build/check:release/Playwright
npm run release         # 同步根产物（436 → 新增 changelog/brand/qr/OG）
git push origin main refactor/v2-astro
```

部署后：

```bash
for p in / /privacy.html /agreement.html /changelog.html /404.html /not-exist-page; do
  curl -s -o /dev/null -w "$p %{http_code}\n" "https://jl.43322.cn$p"; done
curl -I https://jl.43322.cn/ | grep -iE 'content-security|referrer|x-content-type|x-frame|permissions'
curl -I http://jl.43322.cn/ | grep -iE '^HTTP|^location'
npx lighthouse https://jl.43322.cn/changelog.html --only-categories=performance,accessibility,best-practices,seo
```

- 线上 `index.html` 与仓库根产物逐字节一致；
- CI 双 job（Ubuntu 门禁 + macOS 视觉）全绿。

## 明确不做

- 不做国际化/RTL、每功能一页、CMS、后端、表单服务、第三方统计；
- 不热链 Apple CDN 徽章、不伪造官方素材（拿不到就退化为文字 CTA）；
- 不做 `/releases/[version]` 动态子页，只做单页 + 锚点；
- 不在 P1/P2 改 Hero/Header/404，保护既有 70 张基线；
- 不做 HSTS `preload`、不同时维护 `_headers` 与 `edgeone.json`；
- 不在 `verify` 里发起外部网络请求（App Store 外链只做部署后巡检）。
